# 鸟群掠食竞赛 —— 两份 boids 的整合版

**打开方式**：双击 `掠食竞赛.html`（纯前端单文件，无依赖、无需服务器）。
`?compute=cpu|gpu|auto` 切换计算后端（默认 auto：WebGPU 可用且自检通过才启用，否则静默走 CPU）；
`?render=2d` 走原始 Canvas2D 全路径，默认走 WebGL 实例化后端（见 **第 11 节**、**第 12 节**）。
面板「控制」区有 **加入隼（F）/ 加入鹰（E）** 按钮，可随时增援猛禽（见 **第 13 节**）。

> 第 2 轮实现了 A~G 七项新机制（见 **第 8 节**）；第 3 轮状态栏可收起（见 **第 9 节**）；
> 第 4 轮实现四大部分：**采样目标获取 / 雁群中心化重构 / 隼的 (1+1)-ES 策略进化 /
> 雁借椋鸟惊飞网预警**（见 **第 10 节**）；第 5 轮按"先证明物理不是瓶颈、再动渲染"
> 的顺序做了**物理基准 → 零分配热循环 → WebGL 实例化渲染**（见 **第 11 节**）。

## 2. 你贴的那份（B 版，"新 idea"）

*椋鸟群 · 双隼协作 · 学习鹰 —— 掠食竞赛模拟*，在 A 的基础上换了思路：

- **雁群（M=60）领队制 V 编队** —— 有角色记忆的"等级制"对照组，危险时编队解散逃逸、过后自动重组；
- **鹰（Q-learning）** 在线学猎物偏好：状态 =(猎物类型 × 距离档) + 空态，动作 = 追椋鸟/追雁/游荡，奖励 = 吃到的分（椋鸟 1、雁 100）；
- **猛禽只有局部视野**（`perceive()` 无全局视野），休息隼的拦截位由自己视野内的质心推算；
- **环面世界**（四周穿屏，`minImage` 修正）；
- 竞赛计分板 + 重置按钮 + 死亡涟漪/冲击波/能量条等表现层；
- 鹰的冲刺比隼弱、巡航比隼快（耐力型），隼有能量轮换与偶发双打。

## 3. 整合版做了什么

一份文件 `掠食竞赛.html`，4 个种群同场竞赛：**拓扑椋鸟（N 可调）+ 雁 V 编队 + 双隼轮换 + Q 学习鹰**。

### 各自贡献了什么

| 来源 | 保留的内容 | 整合时的处理 |
|---|---|---|
| A 版 | 拓扑邻居（最近 K 只） | 保留，且 K 变成 **3~14 滑杆**；选 K 只用"冒泡插入"，比 A 版"每次重扫最远槽"少一层 O(K) 循环 |
| A 版 | 开阔世界 + 屏幕外缓冲带 + 柔性边界 | **保留为默认几何**（更少穿屏瞬移、猛禽会跟丢猎物，局部视野才有意义）；另给「环面」开关切回 B 版世界 |
| A 版 | 休息隼高速赶往拦截位 | 与 B 版的拦截位几何合并（设伏点到不了就 7.5 速度赶路，到了就 5.0 盘旋） |
| A 版 | 冲刺距离上限 500px | 保留（防止横穿整个世界） |
| A 版 | "按邻居数量选最密个体"当冲刺目标 | **换掉**：那是全局信息，与"猛禽只有局部视野"冲突 → 改用 `perceive()` 视野内最密桶的代表鸟 |
| B 版 | 雁群 V 编队、逃跑时解散 | 全部保留，新增编队引导线可视化 |
| B 版 | 鹰的 Q-learning | 保留 7 态 × 3 动作，**动作 2 从"也朝群体飞"改成真正的伏击**：飞到群体行进方向前方的拦截点且不冲刺 —— 三个动作才真正互斥，Q 表才有意义；并**修掉每帧折扣 0.95（半衰期 14 帧）的缺陷**，改成 0.995，长程追猎的信用才留得住 |
| B 版 | 能量轮换 / 双打 / 60° 冲刺约束 / 拦截位 | 保留 |
| B 版 | 局部视野 `perceive()` | 保留并升级：桶心粗筛 + **逐只精确判距**，质心按几何分别用圆均值/算术均值 |
| B 版 | 计分板与按钮 | 保留，并加捕获数、捕获率、模拟时长、自动补充波次 |

### 两边都没有、这次新加的

1. **小地图**（开阔世界专用）：视口只是世界的一部分，没有全局视图会跟丢猎物；小地图画出世界范围、视口虚线、雁群与猛禽位置、椋鸟抽样点。
2. **猛禽记忆点搜索**：视野为空时飞向"最后一次看到猎物的位置"（300 帧内有效），过期才原地盘旋搜索 —— 局部视野 + 开阔世界必须配记忆，否则会瞎逛。
3. **自动补充**：椋鸟存活 < 35%、雁 < 50% 时，从**离猛禽最远的一侧**补一波（雁直接补回 V 形槽位），让学习过程能长时间观察；可关。
4. **鹰脑可视化**：面板里的 Q 表热力图（行 = 状态、列 = 动作，高亮当前决策单元）+ 食谱比例条（椋鸟 : 雁），能直接看到"它学会了什么"。
5. **时间倍速 0.25×~3×**：想快速看 Q 学习收敛就调到 3×。
6. 三种几何运算统一走 `wrapX/wrapY/minImageX/minImageY`，两套世界共用同一份仿真代码。

## 5. 仿真的物理与参数（都在文件顶部参数区）

- 椋鸟：`MAX_SPEED=3.6`、`PERCEPTION=60`、`SEP_GAIN=4`（距离加权分离）、`TOPOK=7`、极弱质心引力 `0.015`、迁徙倾向 `0.06`。
- 雁：`MAX_SPEED_G=4.4`、编队槽位间距 15、`FORMATION_BREAK=150`（猛禽进 150px 就解散）、领队弱向心。
- 隼：盘旋 5.0 / 冲刺 8.5 / 设伏赶路 7.5；能量 100，冲刺每帧 -0.55，追猎方 +0.40、设伏方 +0.90；低于 25 交棒；±60° 冲刺方向约束。
- 鹰：巡航 5.8（> 雁 4.4，耐力追猎）/ 冲刺 7.2 / 冲刺 18 帧、冷却 60 帧；视野 520；`Q_ALPHA=0.1`、**`Q_GAMMA=0.995`（每帧折扣，半衰期约 140 帧）**、`ε: 0.3→0.08`（0.9995/步衰减）。
- 计分：椋鸟 +1、雁 +100。
- 捕食半径：椋鸟 **9px**、雁 **12px**（第 2 轮 F 收小；死亡即消失并留一圈涟漪）。

**已知取舍**（也写在文件末尾的交接注释里）：

- 椋鸟的质心引力/迁徙力仍用**全局质心**（鸟群"集体属性"的粗信息），只有猛禽被限制为局部视野 —— 否则开阔世界里鸟群会永久飘散到视口外。
- 60° 冲刺约束会让隼偶尔"追着目标转圈对不齐"，这是刻意的特性（限制盘旋角速度带来的真实代价）。
- 鹰的奖励就是原始得分，所以"值 100 分的雁"是稀疏大奖，且第 2 轮的罚款机制（空冲刺 -2/-4、代谢 -0.003/帧）让净奖励变负是常态 —— **三方的分数经常会跑成负数，这是规格明确允许的**（`分数允许为负且面板正常显示`）。第 2 轮实测：24000 帧后鹰吃椋鸟 223 只、雁 1 只，隼靠椋鸟为主，因此谁的分数都不是正数。

## 8. 第 2 轮：A~G 七项新机制的实现与实测

| 项 | 规格要点 | 实现位置 | 实测 |
|---|---|---|---|
| **A 空冲刺扣分** | `dashEats` 字段；EAT 判定里 `if (f.dashT>0) f.dashEats++`；冲刺结束为 0 则隼 -4 / 鹰 -3（鹰同时进 `pending`） | `makeFalcon`/`eagle` 字段、`tryDash`、6.4/6.5 的 EAT、6.6/6.7 的冲刺收尾 | 5000 帧内隼 44 次 / 鹰 35 次；只扣 score，kills/diet 不受影响 |
| **B 代谢成本** | `METAB_CIRCLE 0.002` / `METAB_DASH 0.010` / `METAB_EAGLE 0.003` | 隼两个盘旋分支、冲刺分支；鹰在取 `reward` 之前 `pending -= METAB_EAGLE` | 静态 + 运行计数核对（CIRCLE 4 处 / DASH 3 处 / EAGLE 3 处引用） |
| **C 围攻 mobbing** | 8% 椋鸟当围攻者，170px 内结骚扰环（环外逼近/环内推开，限幅 0.05）；冲刺能耗 ×(1+mob×0.04)；mob≥25 冲刺被打断；非冲刺速度 ×max(0.6,1-mob×0.01)（鹰 0.7 下限、系数减半） | `isMobber`、6.1 帧首清零 `f.mob`、6.4 逃逸之后的骚扰力块、6.6/6.7 的速度与能耗 | 围攻者比例 8.1%；单帧最大 mob=58~66；6000 帧打断 35 次（≈每 170 帧一次，远超"≥1 次/分钟"） |
| **D 迷惑效应** | `tryDash(f,tx,ty,lockIdx)`；椋鸟 EAT 开头 `if (f.dashT>0 && f.lockIdx>=0 && f.lockIdx!==i) continue`；雁的 EAT 不加；冲刺结束解锁；鹰只有 `a===0` 才锁 | `tryDash` 第 4 参、6.4 椋鸟 EAT、6.6/6.7 冲刺触发与收尾 | 5000 帧 67 次带锁定发射；锁定期间只吃被锁那一只 |
| **E 鹰隼互攻** | `raptors` 两两判定；实力=冲刺+2/鹰体型+1.5/眩晕-3/噪声；败方击退 11px+眩晕 90+扣 10+被抢 `floor(score*0.2)`；胜方得分并 `dashEats++`；Q 表第 4 动作"攻隼"（`*3` 全部改 `*N_ACTIONS`）；眩晕白字 | 6.9 节、`stun/clashCd` 字段、6.6/6.7 的眩晕与驱逐冲刺、`renderQ` 第 4 列 | 5000 帧 1~7 次互攻、眩晕最长 88 帧；Q 表 28 格，第 4 列被写入 |
| **F 体型与判定收小** | 椋鸟 2.2/雁 3.2/隼 6.5/鹰 7.5；`EAT_R2_S 12→9`、`EAT_R2_G 15→12`；辉光/标签内收 | `render()` 的 `drawArrow` 调用、`drawHunter` 的 size/glow、能量条与标签位置 | 判定圈 r²=81/144；四类尺寸静态断言通过 |
| **G 收紧鸟群** | `COHESION 2.0 / ALIGNMENT 1.2 / MAX_FORCE 0.15 / SEP 20 / PERCEPTION 50`（CELL、GW/GH 自动跟随；K 仍为 7） | 参数区；`CELL = PERCEPTION` | 无猛禽干扰 30 秒：最近邻平均 15.8→**9.4px**，最大连通团 **99.9%**（不碎裂） |

### 规格之外的两处补充（都为了不破坏已有行为）

1. **`CLASH_CD = 45` 互攻冷却**：规格没写冷却，但两只猛禽贴在一起时会**逐帧**互相判负/扣分，分数会在几秒内崩到 -10⁴ 量级。加了 45 帧冷却后互攻变成偶发事件（实测 5000 帧 1~7 次）。
2. **互攻的分数也要进 `pending`**：胜方抢到的分、败方扣的 10 分，若只改 `score`，鹰的 Q 学习就看不见互攻，第 4 动作永远是 0。所以胜方抢分 `eagle.pending += stolen`、败方（若是鹰）`eagle.pending -= CLASH_COST`。另外被互攻打断的冲刺也走 A 的落空罚款流程。

## 12. 第 6 轮 第 1 步：WebGPU 计算后端（6.1+6.2 上 GPU，原型）

按 WebGPU 迁移方案，第 1 步**只搬 6.1+6.2**（网格 + 拓扑邻居/求力），6.4 与全部"智能"留 CPU。
分段实测（清空某段循环做 A/B）：

| 段 | N=3500 | N=20000 |
|---|---|---|
| 6.2 邻居扫描 + K 选择 + 求力 | **67.7%** | **89.9%** |
| 6.4 积分 + 事件 | 17.0% | 14.9% |
| 6.1 网格重建 | ≤2%（与 6.2 耦合，ablation 测不准） | ≤2% |
| 其余 CPU 系统（60 雁 / 鹰 Q / 隼 ES / 互攻 / 补充） | 0.5 ms（常数，与 N 无关） | 0.5 ms |

### 12.1 实现

- 第三段 `<script>`：`window.ComputeBackend`。WGSL 三趟 pass（均 one-thread-per-bird）：
  `clearGrid`（atomicStore 桶头 -1）→ `insertBirds`（`atomicExchange` 头插链表，即方案 2B
  "原子桶"）→ `neighborForces`（扫 3×3 桶链 → 16 槽寄存器数组升序冒泡插入取最近 topoK →
  与 CPU 逐项同构的力公式写出 ACC）。环面/开阔双模式都在 shader 里。
- buffer（SoA）：`P/V/ACC` 交错 f32、`ALIVE` u32、`HEAD`（`atomic<i32>`）/`NXT` 链表、
  `Params` uniform 64B（16 字段：n/gw/gh/topoK + 8 个物理常量 + torus）、staging 回读。
- **显式 `GPUBindGroupLayout`(7 项) + 共用 `pipelineLayout`**：不能用 `layout:"auto"`
  —— 三趟 pass 静态用到的 binding 不同，自动布局不一致，同一个 bind group 在别的 pass 上
  会直接校验失败。
- 每帧：上行 `P/V/ALIVE`（320 KB @N=20000）→ 三 pass → `copyBufferToBuffer(ACC)` →
  `mapAsync` 回读（第 1 步为量上限用同步等待）→ CPU 跑 `cpuCentroidOnly()`（只算质心，
  与 CPU 版同序、逐位一致）+ `stepRest()`（6.3~6.10）。

### 12.2 自检（关键安全网）

初始化时用同一份状态分别跑 CPU 版与 GPU 版的 6.1+6.2，**逐只活鸟**比较 ACC（死鸟两边都不写，
槽位可能残留 NaN，不参与比较 —— 这是实现时踩到的坑）：最大绝对差 < 1e-4 且无超差项才通过。
不通过就 `dispose()` 并退回 CPU 路径 —— **即便 WGSL 有语义错误，页面只会变慢，不会给出错误物理**。
另加：`getCompilationInfo()` 显式捞 WGSL 编译错误、`uncapturederror` 打控制台、
`device.lost` 让 `ready()` 变 false、运行中任一帧抛错当场退回、启动 3 秒超时保护。

## 10. 第 4 轮：采样目标 / 雁群中心化 / 隼策略进化 / 借网预警

### 10.1 采样目标获取（替换最密桶）

最密网格桶有量化误差，质心还可能正好落在隼自己犁出的空腔正中。现在 `perceive()` 一边收集
可见椋鸟，一边以猛禽为原点布 **5 环 × 16 角 = 80 个极坐标候选点**，每只鸟累加进"距离 <
`SCOOP_R=60` 的候选点"，得到 80 维"捞勺计数"，打分：

```
score(c) = 捞勺内鸟数 × (1 + DIR_LAG·cos(候选方向, 当前航向)) × [锥内乘项]
           // 扩展位：雁权重 / 威慑锥扣分 / mob 扣分
```

argmax = 冲刺中心，中心 `LOCK_R=40px` 内最近的鸟 = `lockIdx`（40px 内无鸟就放弃这次冲刺）。
`tryDash` 的锁定语义不变：冲刺途中只吃得到被锁定那一只（雁的 EAT 不加锁）。内层用
"半径平方 + 预计算角度窗"把每只鸟的候选测试从 80 次压到 5~10 次。

### 10.2 雁群中心化重构

| 项 | 常量 | 效果 |
|---|---|---|
| A 领队智能 | `LEADER_SENSE_R=400` `LEADER_MAX_TURN=0.04` `ESCAPE_HUSTLE=1.15` `LEADER_PANIC_R=250` `GOOSE_MAX_TURN=0.06` | 领队限速转向远离猛禽、近距全队提速；每只雁有转向限速（压坡惯性） |
| B 轮值领队 | `ROTATE_FRAMES=1200` | `slot(i)=(i+gooseShift)%M`，虚拟领队 = 当前 apex 的位置（换岗不瞬移）；实测每 ~1200 帧换一次，没有可斩首的固定领队 |
| C 核心保护 | `JUVENILE_FRAC=0.25` `JUVENILE_DEBUFF_FRAMES=1800` `DEBUFF_FACTOR=0.7` | 幼雁（固定个体，`i%4==0`）永远占内道（实测：幼雁最大排号 8 < 成雁最小排号 9）；幼雁死亡触发全体沮丧期 |
| D 威慑锥 | `CONE_R=180` `CONE_HALF_ANGLE=60°` `CONE_SCORE_FACTOR=0.25` `CONE_FALCON_DASH_MULT=2` `CONE_EAGLE_DRAIN=0.01` | 锥内候选点打分 ×0.25（选目标自己绕开正面）+ 锥内失血（隼冲刺能耗 ×2、鹰 pending −0.01/帧，走价值通道）；只罩正面 120°，绕后不受罚 |
| E 斩首混乱 | `DISARRAY_FRAMES=90` | apex 被吃 → 槽位力关闭、个体径向逃逸，结束后按新 apex 重建（雁相对椋鸟群的结构性弱点） |

### 10.3 隼的 (1+1)-ES 策略进化

制度（能量轮换/拦截位/交棒/驱逐）不学，学制度内的操作参数 —— 鹰学价值、隼学策略。

| 参数 | 映射 | 默认 |
|---|---|---|
| p1 出手能量阈值 | `DASH_MIN ∈[20,60]` | 35 |
| p2 交棒能量阈值 | `ENERGY_LOW ∈[10,40]` | 25 |
| p3 双打能量阈值 | `DOUBLE_TEAM_E ∈[60,95]` | 85 |
| p4 拦截位外推 | `INTERCEPT_AHEAD ∈[0.3,0.8]` | 0.55 |
| p5 mob 容忍 | 乘在 `DASH_DRAIN` 的 mob 项上 `∈[0,2]` | 1.0 |
| p6 线性冲刺策略 | 4 维特征 + 阈值 | 留作扩展位（未实现，见文件交接说明） |

算法：`ES_EVAL_FRAMES=3600`（60 秒）一个评估期，偶数期跑当前参数、奇数期跑
"当前 + N(0, 0.1) 截断"的候选，期末配对比较，候选更好就采纳否则回滚；两只隼各抽各的噪声。
适应度 = `Δscore − 2·Σ落空罚款 − 5·Σ代谢成本`。纯爬山，允许学成"永不出手"的局部最优。
面板有「重置隼策」，`SIM.falconPolicies` 可读参数/代数/适应度，每只隼能量条上方显示"策略 n 代"。

### 10.4 雁的借网预警

新增 `PV` 存上帧速度，惊飞判据 = 相邻两帧速度夹角 > 60°（**不是速度大小**：椋鸟平时也贴满速）。
雁查周边 3×3 桶里 `ALERT_R=140` 内的惊飞椋鸟，≥`ALERT_N=3` 只就视同猛禽进入
`FORMATION_BREAK`，逃逸方向直接跟"惊飞椋鸟的平均速度方向"（跟流）。与自身 150px 感知取并集。
涌现代价不修：椋鸟翻滚会致误报，雁散一下又合拢 —— 偷听公共信息的真实成本（面板能看到次数）。
